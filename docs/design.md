# Gitview · 设计说明

用户偶尔打开插件，了解已有项目状态，再决定让 Codex 做什么。首屏主角是分支与提交图。

唯一视觉方向：贴合 Codex 的原生明暗面板，沿用低对比背景、系统字体与紧凑控件。借鉴用户提供的 Oil Git 截图的纵向轨道、提交标题、分支标签与按需右侧详情结构。

信息层级：项目/当前位置/修改数量 → 提交与分支关系 → 点击后的分支或提交详情 → 点击文件后的代码差异。首页没有截图、AI 说明卡片、署名设置或 Git 操作按钮。

一个节点是一次真实提交；同位置的多个分支共用节点。轨道展示真实父子关系；虚线只用于未提交修改和未加载历史。当前 HEAD 强调，分支名和提交标题保留原文。日期服从拓扑顺序，不按日期重新排序。

宽屏在右侧展开详情，窄屏使用覆盖层；关闭详情保留选择与浏览位置。长标题在图中截断，详情显示完整文本；完整提交标识、作者邮箱与原始说明默认折叠。

次要操作：「交给 Codex」位于详情底部，先编辑请求草稿，再发送。插件不直接执行 Git 写操作。

三处动效：首次进入 220ms 淡入/4px 位移；详情层 180ms 侧向出现；节点选择背景和按钮反馈 120–180ms。减少动态效果时立即到位，不等待动画后才更新业务状态。

关键状态：连接中/失败、非 Git 文件夹、无提交、脱离分支、冲突/合并/变基、浅克隆、历史窗口及延续、分支变化后的过期游标、详情加载/失败、请求发送中/失败。

验证证据与独立评审结果见 verification.md。旧版页面预览、成果卡片和保存/恢复文案已从产品主流程移除。
